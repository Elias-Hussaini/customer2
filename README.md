# E-managment — سامانه مدیریت ویزا

سامانه‌ای **محلی (Local-first)** برای مدیریت مشتریان، نمایندگان، درخواست‌های ویزا، پرداخت‌ها و مدارک — با طراحی گلس پریمیوم، کاملاً فارسی و راست‌به‌چپ، تقویم شمسی و نصب به‌صورت PWA.

> **مهم:** همه داده‌ها فقط در **مرورگر خودتان** (IndexedDB) ذخیره می‌شوند. هیچ سروری در کار نیست و هیچ داده‌ای جای دیگری ارسال نمی‌شود. بین دستگاه‌ها هم‌گام‌سازی خودکار وجود ندارد — برای انتقال داده از **پشتیبان JSON** استفاده کنید.

## امکانات

- **لیست‌ها و پوشه‌بندی**: لیست با بازه تاریخ (از … تا …)، دسته‌بندی و توضیحات؛ انتقال درخواست بین لیست‌ها بدون کپی
- **نمایندگان**: پرونده مستقل هر نماینده با آمار درخواست، ویزاهای صادرشده، مشتریان، مطالبات/دریافتی/مانده به تفکیک ارز و تاریخچه پرداخت‌ها
- **مشتریان**: هر مشتری حتماً در یک **لیست** و زیر یک **نماینده** ثبت می‌شود (با یادآوری آخرین انتخاب)، عکس پاسپورت/روی تذکره/پشت تذکره + مدارک دلخواه، هشدار پاسپورت تکراری
- **درخواست ویزا**: موجودیتی جدا از مشتری (هر مشتری چند درخواست)، تیک «صادر شده» با تاریخ صدور و قابلیت لغو + ثبت تاریخچه؛ مشتری، نماینده و لیست الزامی هستند
- **فیلدهای سفارشی**: از تنظیمات، بدون کدنویسی فیلد جدید (متن، عدد، تاریخ، انتخابی، چندگزینه‌ای، چک‌باکس، لینک) به فرم مشتری یا درخواست اضافه کنید
- **تگ‌های داینامیک**: ساخت/رنگ‌بندی/بایگانی تگ؛ تگِ «فوری» در شمارنده‌های داشبورد لحاظ می‌شود
- **مالی**: مبلغ هر درخواست با انتخاب ارز (دلار/تومان)، ثبت پرداخت‌های جزئی، مانده حساب جدا برای هر ارز (هیچ‌وقت با هم جمع نمی‌شوند)
- **جستجوی سراسری قوی**: نام، پاسپورت، تلفن، نوع ویزا، تگ، یادداشت و فیلدهای سفارشی — با نرمال‌سازی ی/ي، ک/ك و ارقام فارسی/عربی
- **گزارش و خروجی**: خروجی **اکسل (RTL)**، CSV، **PDF با متن فارسی سالم** و **تصویر PNG** از هر لیست، مشتری، نماینده یا بازه تاریخ دلخواه + انتخاب ستون‌ها
- **پشتیبان‌گیری**: فایل JSON کامل (بدون عکس‌ها)، بایگانی ZIP تصاویر، پشتیبان **رمزنگاری‌شده (AES-GCM)** و بازیابی با پیش‌نمایش و گزینه ادغام/جایگزینی
- **تاریخ شمسی**: تقویم انتخاب تاریخ، تاریخ ثبت خودکارِ امروز، نمایش فارسی همه‌جا؛ تاریخ تولد و تاریخ پاسپورت از تنظیمات قابل انتخاب است: **میلادی (پیش‌فرض) یا شمسی**
- **ورود سریع**: یادآوری آخرین نماینده/لیست، ساخت سریع مشتری داخل فرم، مقادیر پیش‌فرض
- **PWA**: نصب روی گوشی/دسکتاپ، کارکرد آفلاین کامل، اعلان به‌روزرسانی نسخه جدید
- تم روشن/تاریک، آرشیو به‌جای حذف، تاریخچه فعالیت‌ها، طراحی واکنش‌گرا (موبایل و دسکتاپ)

## نصب و اجرا (Windows PowerShell)

```powershell
# دریافت سورس
git clone https://github.com/Elias-Hussaini/customer2.git
cd customer2

# نصب وابستگی‌ها
npm install

# اجرای محیط توسعه (http://localhost:5173)
npm run dev
```

اگر مخزن را قبلاً کلون کرده‌اید و فقط می‌خواهید آخرین تغییرات را بگیرید:

```powershell
git pull
npm install
```

## ساخت نسخه نهایی

```powershell
# ساخت خروجی در پوشه dist
npm run build

# پیش‌نمایش نسخه ساخته‌شده (شبیه GitHub Pages)
npm run preview
```

خروجی `dist` شامل `index.html`، `404.html` (برای مسیرهای SPA)، فایل‌های PWA (مانیفست و سرویس‌ورکر) و آیکون‌ها است.

## استقرار روی GitHub Pages

استقرار **کاملاً خودکار** است:

1. تغییرات را روی شاخه `main` پوش کنید:
   ```powershell
   git add .
   git commit -m "your message"
   git push
   ```
2. GitHub Actions (فایل `.github/workflows/deploy.yml`) به‌صورت خودکار build می‌گیرد و منتشر می‌کند.
3. فقط **یک بار** این تنظیم را انجام دهید: در مخزن، مسیر
   **Settings → Pages → Build and deployment → Source** را روی **GitHub Actions** بگذارید.
4. پس از چند دقیقه، برنامه در آدرس زیر در دسترس است:
   `https://elias-hussaini.github.io/customer2/`

> آدرس پایه (`base`) در `vite.config.ts` برابر `/customer2/` تنظیم شده است. اگر مخزن را جابه‌جا یا تغییر نام دادید، ثابت `REPO_NAME` را در همان فایل اصلاح کنید.

## نصب به‌صورت برنامه (PWA)

- **اندروید (Chrome):** صفحه را باز کنید → منوی ⋮ → **Add to Home screen / نصب برنامه**
- **iOS (Safari):** دکمه اشتراک ← **Add to Home Screen**
- **دسکتاپ (Chrome/Edge):** آیکون نصب در نوار آدرس

پس از اولین بازدید، فایل‌های برنامه کش می‌شوند و برنامه **بدون اینترنت** هم باز می‌شود. وقتی نسخه جدیدی منتشر شود، داخل برنامه پیام «به‌روزرسانی» ظاهر می‌شود.

## پشتیبان‌گیری و بازیابی

از منوی **بیشتر ← پشتیبان‌گیری**:

| کار | توضیح |
|---|---|
| **پشتیبان JSON** | همه رکوردها + تنظیمات (بدون تصاویر) — برای بکاپ منظم |
| **بایگانی ZIP** | همه عکس‌ها و پیوست‌ها، به تفکیک پوشه هر مشتری |
| **پشتیبان رمزنگاری‌شده** | همان JSON ولی با رمز عبور (AES-GCM + PBKDF2) |
| **بازیابی** | ابتدا پیش‌نمایش (تعداد رکوردها و موارد تکراری) → سپس «ادغام» یا «جایگزینی کامل» |

⚠️ پاک کردن داده مرورگر، خروج از پروفایل یا از دست دادن دستگاه = از بین رفتن داده‌ها. **پشتیبان‌های دانلودشده را جای امنی نگه دارید.**

> بازیابی فایل JSON، تصاویر را برنمی‌گرداند — برای انتقال کامل به دستگاه دیگر، ZIP پیوست‌ها را هم دانلود کنید.

## داده نمونه

اگر برنامه خالی است: **تنظیمات ← مدیریت داده ← بارگذاری داده نمونه** (فقط زمانی فعال است که هیچ رکوردی نداشته باشید).

## ساختار پروژه

```
src/
├── components/
│   ├── ui/          # کامپوننت‌های پایه (دکمه، فیلد، مودال، باتم‌شیت، تقویم شمسی، جدول داده…)
│   ├── layout/      # پوسته برنامه، TopBar، داک شناور، شیت «بیشتر»
│   ├── domain/      # فرم‌های مشتری/نماینده/لیست/پرداخت و جدول درخواست‌ها
│   └── exports/     # دیالوگ خروجی و سند چاپی (PDF/PNG)
├── db/              # اسکیمای Dexie (IndexedDB) + مخازن داده + داده نمونه
├── hooks/           # هوک‌های تم، توست، تأییدیه، اتصال زنده دیتابیس
├── pages/           # صفحات (داشبورد، لیست‌ها، مشتریان، نمایندگان، درخواست‌ها، پرداخت‌ها، گزارش‌ها، جستجو، آرشیو، پشتیبان، تنظیمات)
├── services/        # جستجوی سراسری و محاسبات آماری
├── utils/           # تاریخ شمسی، اعداد و پول، نرمال‌سازی فارسی، خروجی‌ها، پشتیبان
├── pwa/             # اتصال جریان به‌روزرسانی سرویس‌ورکر
└── types/           # تایپ‌های دامنه
```

## نکات امنیتی و حریم خصوصی

- داده‌ها (از جمله عکس پاسپورت و تذکره) فقط در IndexedDB همان مرورگر می‌مانند و به هیچ سرویس خارجی ارسال نمی‌شوند.
- هیچ آنالیتیکس یا درخواست خارجی در برنامه وجود ندارد.
- **هیچ داده واقعی مشتری را داخل خود مخزن گیت (پوشه‌های پروژه) قرار ندهید** — پشتیبان‌ها را جداگانه و امن نگه دارید.
- رمز عبور پشتیبان رمزنگاری‌شده در هیچ جای برنامه ذخیره نمی‌شود؛ فراموشی آن = عدم امکان بازیابی.
- این برنامه تک‌کاربره و محلی است؛ سیستم لاگین چندکاربره ندارد.

## رفع اشکال

| مشکل | راه‌حل |
|---|---|
| بعد از پوش، صفحه Pages آپدیت نمی‌شود | تب Actions مخزن را چک کنید؛ Source صفحات باید GitHub Actions باشد |
| صفحه ۴۰۴ با رفرش مسیرها | مطمئن شوید workflow اجرا شده و فایل `404.html` در deploy هست |
| داده‌ها ناپدید شدند | پروفایل/مرورگر دیگری را باز نکرده‌اید؟ از فایل پشتیبان بازیابی کنید |
| تغییر آدرس مخزن | `REPO_NAME` در `vite.config.ts` را اصلاح و دوباره پوش کنید |
